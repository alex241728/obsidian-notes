A **slice** is a special kind of reference that points to a **contiguous sequence of elements** in a collection rather than the entire collection. Slices do not take ownership.

---

# 1. The Motivation: Decoupling State vs. Indices

When returning an index (e.g., `usize`) pointing to a substring or collection item, the index becomes detached from the underlying data:

```rust
let mut s = String::from("hello world");
let word_idx = 5; // Suppose index returned by manual byte-scanning
s.clear();        // s is now empty "", but word_idx is still 5!
```

* **Problem**: The index `word_idx` is still valid code-wise, but logically invalidated because the string changed.
* **Solution**: Slices tie the reference directly to the lifetime and borrow state of the source data.

---

# 2. String Slices (`&str`)

A string slice contains two elements stored on the stack:
1. A **pointer** to the starting byte.
2. A **length** (number of elements/bytes).

```rust
let s = String::from("hello world");

let hello = &s[0..5]; // Starts at index 0, length = 5
let world = &s[6..11]; // Starts at index 6, length = 5
```

## Range Syntax Shortcuts (`..`)
```rust
let s = String::from("hello");
let slice1 = &s[0..2];
let slice1 = &s[..2];  // Omitting the start assumes index 0

let len = s.len();
let slice2 = &s[3..len];
let slice2 = &s[3..];  // Omitting the end assumes len

let slice3 = &s[0..len];
let slice3 = &s[..];   // Slices the entire string
```

> [!danger] UTF-8 Boundary Rule
> String slice indices **must occur at valid UTF-8 character boundaries**. Slicing in the middle of a multibyte character causes a runtime panic.

# 3. Compile-Time Memory Safety with Slices

Slices participate in the borrowing rules as **immutable references (`&`)**:

```rust
fn main() {
    let mut s = String::from("hello world");

    let word = first_word(&s); // word holds an immutable slice (&str) borrowing `s`

    // s.clear(); // ERROR: E0502 (cannot borrow `s` as mutable while borrowed as immutable)

    println!("the first word is: {word}"); // Immutable borrow is active here
}
```

Because `clear()` requires a mutable reference (`&mut s`), the compiler rejects mutating or invalidating `s` while the slice `word` remains active.

# 4. Idiomatic Function Signatures: Deref Coercion

* **String literals are slices**: `let s = "Hello, world!";` has the type `&str` pointing directly to binary memory.
* **Idiomatic Parameter Design**: Prefer `&str` over `&String` for function parameters:

```rust
// Idiomatic & flexible:
fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[..i];
        }
    }

    &s[..]
}
```

Passing a `&String` to a function expecting `&str` works seamlessly via **deref coercion**, allowing one implementation to accept both owned strings and string literals:

```rust
let my_string = String::from("hello world");
first_word(&my_string[0..6]); // Slices of String
first_word(&my_string);       // Reference to String (deref-coerced to &str)

let my_literal = "hello world";
first_word(my_literal);       // String literal (&str directly)
```

# 5. Other Collection Slices

Slices generalize to arrays and other linear collections:

```rust
let a = [1, 2, 3, 4, 5];
let slice: &[i32] = &a[1..3]; // References &[2, 3]

assert_eq!(slice, &[2, 3]);
```

* **Type**: Written as `&[T]` (e.g., `&[i32]`).
* **Internals**: Stores a pointer to the first item and an element count, allocated on the stack.
