A **struct** (or structure) is a custom composite data type that packages together and names multiple related values into a unified group. Unlike tuples, struct fields are named rather than indexed, providing greater clarity, flexibility, and maintainability.

---

# 1. Defining Structs

To define a struct, use the `struct` keyword, provide a descriptive type name in `PascalCase`, and declare the fields and their types within curly braces:

```rust
struct User {
    active: bool,
    username: String,
    email: String,
    sign_in_count: u64,
}
```

---

# 2. Creating Instances

- Instances are created by specifying `key: value` pairs in curly braces. Fields do not need to be declared in the order they were defined
- If the instance is mutable, we can change a value by using the dot notation and assigning into a particular field.

```rust
fn main() {
    let mut user1 = User {
        active: true,
        username: String::from("someusername123"),
        email: String::from("someone@example.com"),
        sign_in_count: 1,
    };
    
    user1.email = String::from("anotheremail@example.com");
}
```

> [!important] All-or-Nothing Mutability
> Rust does **not** allow marking only specific fields as mutable. The entire instance must be declared mutable (`let mut`) for any of its fields to be modified.

## Returning Instances from Functions

As with any expression in Rust, a struct instance can be returned implicitly as the last expression of a function:

```rust
fn build_user(email: String, username: String) -> User {
    User {
        active: true,
        username: username,
        email: email,
        sign_in_count: 1,
    }
}
```

## Field Init Shorthand

When function parameters and struct fields have the exact same name, repeating `field: field` can be simplified using the **field init shorthand**:

```rust
fn build_user(email: String, username: String) -> User {
    User {
        active: true,
        username, // Shorthand for username: username
        email,    // Shorthand for email: email
        sign_in_count: 1,
    }
}
```

# 3. Updating Instances

Struct update syntax allows creating a new instance by explicitly specifying certain fields while copying or moving the remaining fields from an existing instance:

```rust
fn main() {
    let user1 = build_user(
        String::from("someone@example.com"),
        String::from("someusername123"),
    );

    // Creates user2 with a new email, reusing remaining fields from user1
    let user2 = User {
        email: String::from("another@example.com"),
        ..user1 // Must come last
    };
}
```

## Ownership and Move Semantics in Updates

Struct update syntax uses `=` assignment semantics, which moves non-`Copy` data:

* **Moved Fields**: In the example above, `user1.username` (`String`) is moved into `user2`. As a result, `user1` is **no longer valid as a whole** and cannot be used.
* **Stack / Copy Types**: Scalar fields (`active: bool`, `sign_in_count: u64`) implement the `Copy` trait and are duplicated on the stack without invalidating `user1`.
* **Preserving the Original Instance**: If `user2` had provided new `String` values for both `email` and `username`, only `Copy` fields would be taken from `user1`, leaving `user1` fully valid.

# 4. Tuple Structs

Tuple structs have a named type but unnamed, indexed fields. They are useful when giving the overall tuple a distinct type name without verbose field names:

```rust
struct Color(i32, i32, i32);
struct Point(i32, i32, i32);

fn main() {
    let black = Color(0, 0, 0);
    let origin = Point(0, 0, 0);

    // Access individual fields via dot index
    println!("Origin X: {}", origin.0);

    // Destructuring (requires the type name)
    let Point(x, y, z) = origin;
}
```

* **Nominal Typing**: `Color` and `Point` are completely distinct types despite identical layout (`i32, i32, i32`). A function expecting `Color` will reject a `Point` at compile time.

# 5. Unit-Like Structs
Structs can also be declared without any fields, behaving similarly to the unit type `()`:

```rust
struct AlwaysEqual;

fn main() {
    let subject = AlwaysEqual; // No parentheses or curly braces
}
```

* **Use Case**: Typically used to implement traits on a type when no internal state or data needs to be stored (e.g., marker types or mock behaviour for testing).

# 5. Ownership of Struct Data

Using owned types like `String` ensures the struct instance owns its data and remains valid for its entire lifecycle.

```rust
// ILLEGAL: Missing lifetime specifiers (E0106)
struct User {
    active: bool,
    username: &str, // ERROR: expected named lifetime parameter
    email: &str,
    sign_in_count: u64,
}
```

# 6. Refactoring with Structs: An Area Example

To see how structs improve code architecture, compare three approaches to calculating the area of a rectangle:

| Approach | Signature | Trade-offs |
| :--- | :--- | :--- |
| **Separate Variables** | `fn area(width: u32, height: u32) -> u32` | Parameters are logically related but decoupled in code. |
| **Tuples** | `fn area(dimensions: (u32, u32)) -> u32` | Groups data, but anonymous indices (`.0`, `.1`) obscure meaning. |
| **Structs** | `fn area(rectangle: &Rectangle) -> u32` | Self-documenting; names the entity and its individual dimensions. |

### Idiomatic Struct Implementation
```rust
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    // Pass an immutable reference (&rect1) so main retains ownership
    println!(
        "The area of the rectangle is {} square pixels.",
        area(&rect1)
    );
}

fn area(rectangle: &Rectangle) -> u32 {
    rectangle.width * rectangle.height
}
```

* **Borrowing via `&Rectangle`**: Passing `&rect1` avoids transferring ownership (`E0382`). Field access on a borrowed struct does not move field values.

# 7. Printing & Debugging Structs

By default, custom structs do not implement the `Display` trait used by `{}` in `println!` (`E0277`), as there is no single standard way to format arbitrary structs.

## The `Debug` Trait (`#[derive(Debug)]`)
To inspect structs during development, opt in by adding the `#[derive(Debug)]` outer attribute:

```rust
#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    // Standard Debug format: {:?}
    println!("rect1 is {:?}", rect1); // rect1 is Rectangle { width: 30, height: 50 }

    // Pretty-printed Debug format: {:#?}
    println!("rect1 is {:#?}", rect1);
}
```

## The `dbg!` Macro
The `dbg!` macro evaluates an expression, prints file/line metadata and value to `stderr`, and returns ownership of the evaluated value:

```rust
fn main() {
    let scale = 2;
    let rect1 = Rectangle {
        width: dbg!(30 * scale), // Prints to stderr: [src/main.rs:10:16] 30 * scale = 60
        height: 50,
    };

    dbg!(&rect1); // Pass reference to prevent dbg! from taking ownership
}
```

| Feature | `println!` | `dbg!` |
| :--- | :--- | :--- |
| **Target Stream** | Standard Output (`stdout`) | Standard Error (`stderr`) |
| **Ownership** | Borrows its arguments | Takes ownership and returns the value |
| **Metadata** | Formatted string only | Outputs file path, line number, and expression |
