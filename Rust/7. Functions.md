# 1. Function Declarations & Signatures

* **Naming Style**: Uses `snake_case` convention.
* **Order Independence**: Functions can be defined before or after the caller as long as they reside within a visible lexical scope.
* **Mandatory Type Annotations**: Every parameter in a function signature **must** have an explicitly declared type. The compiler uses these annotations to infer types throughout the rest of the codebase.

```rust
fn print_labeled_measurement(value: i32, unit_label: char) {
    println!("The measurement is: {value}{unit_label}");
}
```

# 2. Statements vs. Expressions

Rust is fundamentally an **expression-oriented** language.

| Concept | Definition | Return Value | Example |
| :--- | :--- | :--- | :--- |
| **Statement** | Instruction that performs an action. | None (evaluates to unit type `()`) | `let y = 6;`, function definitions |
| **Expression** | Evaluates to a concrete resultant value. | Evaluates to a value | `5 + 6`, function/macro calls, `{ ... }` blocks |

## Critical Differences & Traps

* **Assignments do not evaluate to values**:
  Unlike C or Python, variable assignments cannot be chained or assigned as expressions:
  ```rust
  let x = (let y = 6); // ERROR: `let` is a statement, not an expression
  ```

* **Scope Blocks as Expressions**:
  A block enclosed in `{}` evaluates to the value of its final expression:
  ```rust
  let y = {
      let x = 3;
      x + 1 // Note: No semicolon here
  }; // y binds to 4
  ```

# 3. Function Return Values

Functions declare return types using an arrow (`-> Type`). 

```rust
fn plus_one(x: i32) -> i32 {
    x + 1 // Implicit return of the tail expression
}
```

* **Implicit Return**: The return value of a function matches the value of the **final expression** (tail expression) in its body block.
* **Early Return**: The `return` keyword can be used to exit a function early.

> [!danger] The Semicolon Trap (`E0308`)
> Adding a semicolon `;` converts an expression into a statement.
> Statements evaluate to the unit type `()`.
> 
> ```rust
> fn plus_one(x: i32) -> i32 {
>     x + 1; // ERROR: expected `i32`, found `()`
> }
> ```
> Appending `;` suppresses the value, causing a compile-time type mismatch error (`E0308`).
