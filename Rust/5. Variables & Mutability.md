# 1. Immutability by Default vs. `mut`

In Rust, all variable bindings declared with `let` are **immutable by default**. Attempting to reassign a value to an immutable binding causes compile-time error `E0384` (`cannot assign twice to immutable variable`).

```rust
let x = 5;
// x = 6; // ERROR: E0384

let mut y = 5;
y = 6; // OK: Explicitly opted into mutability
```

- **Why default to immutability?** Eliminates data-race bugs, reduces unexpected side effects, and enables clear reasoning in concurrent contexts.
- **Explicit Intent**: Adding `mut` explicitly communicates to the compiler and future readers that the value is meant to change throughout its lifetime.

# 2. Constants (`const`) vs. Immutable Variables (`let`)

Constants represent fixed, hardcoded values available across any lexical or global scope.

```rust
const THREE_HOURS_IN_SECONDS: u32 = 60 * 60 * 3;
```

| Dimension | Immutable Variable (`let`) | Constant (`const`) |
| :--- | :--- | :--- |
| **Mutability** | Immutable by default (`mut` allowed) | **Always immutable** (`mut` forbidden) |
| **Type Annotation** | Optional (compiler uses type inference) | **Mandatory** (`const NAME: Type = ...`) |
| **Value Resolution** | Evaluated at runtime or compile time | **Must be a compile-time constant expression** |
| **Scope** | Block / lexical scope | Any scope, including **global scope** |
| **Naming Convention** | `snake_case` | `SCREAMING_SNAKE_CASE` |

# 3. Variable Shadowing

Shadowing occurs when a new variable is declared using the `let` keyword with the same name as an existing variable in scope. The new declaration **overshadows** the previous binding.

## Scoping & Lifecycle
```rust
fn main() {
    let x = 5;
    let x = x + 1; // x is now 6

    {
        let x = x * 2; // Shadows outer x within this inner block
        println!("Inner scope x = {x}"); // Outputs: 12
    }

    println!("Outer scope x = {x}"); // Outputs: 6 (inner shadowing ended)
}
```

## Shadowing vs. `mut`

| Feature | Shadowing (`let x = ...; let x = ...;`) | Mutability (`let mut x = ...; x = ...;`) |
| :--- | :--- | :--- |
| **Type Change** | **Allowed**: Creates a completely new variable binding. | **Forbidden**: Variable type is permanently fixed (`E0308`). |
| **Post-State** | Target remains **immutable** unless marked `let mut`. | Target remains **mutable**. |
| **Reassignment Safety** | Accidentally omitting `let` triggers a compile-time error. | Silently mutates existing memory. |

```rust
// Shadowing: Changes type cleanly without synthetic variable names
let spaces = "   ";          // &str
let spaces = spaces.len();   // usize (OK)

// Mutability: Cannot change type
let mut spaces = "   ";
// spaces = spaces.len();    // ERROR: mismatched types (expected `&str`, found `usize`)
```
