An **enum** (enumeration) is a custom type that allows a value to be one of a discrete set of possible variants. While structs group multiple related fields into a single product type, enums represent a choice between mutually exclusive possibilities (sum types).

---

# 1. Defining and Instantiating Enums

Enums are declared using the `enum` keyword followed by variant names in `PascalCase`:

```rust
enum IpAddrKind {
    V4,
    V6,
}
```

## Instantiating and Namespacing (`::`)
Enum variants are namespaced under the enum identifier and accessed via the double colon (`::`) syntax:

```rust
let four = IpAddrKind::V4;
let six = IpAddrKind::V6;
```

* **Uniform Type**: Both `IpAddrKind::V4` and `IpAddrKind::V6` share the same overarching type (`IpAddrKind`).
* **Function Parameters**: Functions can accept the enum type to handle any of its variants interchangeably:

```rust
fn route(ip_kind: IpAddrKind) {
    // Logic that applies to any IP kind
}

fn main() {
    route(IpAddrKind::V4);
    route(IpAddrKind::V6);
}
```

# 2. Embedding Data Directly into Variants

Instead of wrapping an enum within a struct to associate data with each variant, Rust allows storing data **directly inside the enum variants**.

## The Anti-Pattern: Enum Inside a Struct
```rust
enum IpAddrKind {
    V4,
    V6,
}

struct IpAddr {
    kind: IpAddrKind,
    address: String,
}

let home = IpAddr {
    kind: IpAddrKind::V4,
    address: String::from("127.0.0.1"),
};
```

## The Idiomatic Solution: Direct Data Attachment
```rust
enum IpAddr {
    V4(String),
    V6(String),
}

let home = IpAddr::V4(String::from("127.0.0.1"));
let loopback = IpAddr::V6(String::from("::1"));
```

* **Automatic Constructor Functions**: Defining an enum variant with data (e.g., `IpAddr::V4(...)`) automatically creates an associated constructor function that accepts the specified arguments and returns an instance of the enum.

## Heterogeneous Variant Data
Each variant can hold **different types and quantities** of associated data:

```rust
enum IpAddr {
    V4(u8, u8, u8, u8), // Four 8-bit octets
    V6(String),          // Hexadecimal string representation
}

let home = IpAddr::V4(127, 0, 0, 1);
let loopback = IpAddr::V6(String::from("::1"));
```

### Standard Library Approach (`std::net::IpAddr`)
Variants can encapsulate arbitrary types, including structs and other enums:

```rust
struct Ipv4Addr { /* ... */ }
struct Ipv6Addr { /* ... */ }

enum IpAddr {
    V4(Ipv4Addr),
    V6(Ipv6Addr),
}
```

# 3. Rich Variant Types: The `Message` Enum

A single enum can combine unit-like, tuple-like, and struct-like variants under one unified type:

```rust
enum Message {
    Quit,                       // No associated data (unit-like)
    Move { x: i32, y: i32 },    // Named fields (struct-like)
    Write(String),              // Single tuple value
    ChangeColor(i32, i32, i32), // Multiple tuple values
}
```

### Enum Variants vs. Separate Structs

| Approach | Definition | Trade-offs |
| :--- | :--- | :--- |
| **Enum** | `enum Message { ... }` | All variants share the **single type `Message`**. Functions and collections can easily store and process any message variant. |
| **Separate Structs** | `struct QuitMessage;`<br>`struct MoveMessage { x: i32, y: i32 }`<br>`struct WriteMessage(String);`<br>`struct ChangeColorMessage(i32, i32, i32);` | Each struct is a **distinct type**. Writing a generic handler or collection requires traits or complex polymorphism. |

# 4. Defining Methods on Enums (`impl`)

Just like structs, enums support methods defined within an `impl` block:

```rust
impl Message {
    fn call(&self) {
        // self refers to the specific variant instance invoking the method
    }
}

fn main() {
    let m = Message::Write(String::from("hello"));
    m.call();
}
```

# 5. The `Option<T>` Enum: Eliminating Null

Rust deliberately excludes `null` references to prevent null pointer exceptions, famously termed by Tony Hoare as his **"Billion-Dollar Mistake"**:

> *"I call it my billion-dollar mistake. ... I couldn't resist the temptation to put in a null reference, simply because it was so easy to implement. This has led to innumerable errors, vulnerabilities, and system crashes..."*
> — **Tony Hoare**

## The `Option<T>` Definition
In Rust, the presence or absence of a value is explicitly modeled via the standard library enum `Option<T>`:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

* **Prelude Inclusion**: Both `Option<T>` and its variants (`Some`, `None`) are included in the Rust prelude; they can be used directly without explicit `Option::` prefixing or importing.
* **Generic Parameter `<T>`**: `<T>` allows `Some` to wrap a value of any arbitrary type:

```rust
let some_number = Some(5);              // Inferred as Option<i32>
let some_char = Some('e');              // Inferred as Option<char>
let absent_number: Option<i32> = None;  // Explicit type annotation required for None
```

## Why `Option<T>` is Superior to `null`

1. **Type Separation**: `Option<T>` and `T` are distinct types. The compiler forbids performing operations on an `Option<T>` as if it were a guaranteed `T`:

```rust
let x: i8 = 5;
let y: Option<i8> = Some(5);

// ILLEGAL: Compile-time error E0277
// let sum = x + y; // ERROR: cannot add `Option<i8>` to `i8`
```

2. **Guaranteed Non-Nullability**: Any variable with a standard type (e.g., `i8`, `String`, `Rectangle`) is **guaranteed by the compiler to always hold a valid value**.
3. **Explicit Opt-in for Absence**: A value can only be absent if its type is explicitly declared as `Option<T>`. Code that handles this value is required by the compiler to account for the `None` case before accessing the underlying `T`.

# 6. Extracting Values: Transition to Pattern Matching

To compute with the inner `T` stored inside a `Some(T)`, the value must be safely unpacked.

```rust
// Requires unwrapping or pattern matching before accessing T:
let maybe_num: Option<i32> = Some(10);
```

* Standard library helper methods (e.g., `.unwrap_or()`, `.is_some()`, `.map()`) provide quick transformations.
* For robust handling of all variants in enums, Rust provides the **`match` expression**.

---

> [!tip] Looking Ahead: Pattern Matching (`match` & `if let`)
> The `match` control flow construct enforces **exhaustive pattern matching** at compile time, guaranteeing that code handles both `Some(T)` and `None` (or every variant of a custom enum) before the application can compile.
