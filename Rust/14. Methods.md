A **method** is a function defined within the context of a `struct`, `enum`, or trait object. Methods differ from standard functions in that their first parameter is always `self`, which represents the instance of the type on which the method is invoked.

---

# 1. Method Syntax & The `impl` Block

To define methods for a type, create an **`impl` (implementation) block**. All functions declared within this block are associated with that type.

```rust
#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    // &self borrows the Rectangle instance immutably
    fn area(&self) -> u32 {
        self.width * self.height
    }
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    // Method call syntax using dot notation
    println!("The area of the rectangle is {} square pixels.", rect1.area());
}
```

## `Self` vs. `self`
* **`Self` (uppercase)**: A type alias for the type the `impl` block is implementing (here, `Rectangle`).
* **`self` (lowercase)**: The parameter variable representing the concrete instance invoking the method.
* **Shorthand**: `&self` is syntactic sugar for `self: &Self`.

---

# 2. Method Receivers: Ownership and Mutability

The first parameter of a method dictates how it interacts with the instance's ownership and memory:

| Receiver Syntax | Desugared Signature | Access Level | Description & Use Case |
| :--- | :--- | :--- | :--- |
| **`&self`** | `self: &Self` | Immutable borrow | **Most common**. Reads data without modifying fields or taking ownership. |
| **`&mut self`** | `self: &mut Self` | Mutable borrow | Mutates the instance's fields in-place. |
| **`self`** | `self: Self` | Consumes ownership | Rare. Takes ownership of the instance, consuming it and preventing caller reuse (e.g., transforming `self` into another type). |

> [!tip] Organizational Advantage
> Beyond providing dot-notation call syntax, `impl` blocks organize all domain behaviour directly alongside the type definition, preventing consumers from having to search across disparate library functions.

# 3. Method-Field Disambiguation & Getters

In Rust, a method can share the exact same name as a struct field:

```rust
impl Rectangle {
    fn width(&self) -> bool {
        self.width > 0
    }
}

fn main() {
    let rect1 = Rectangle { width: 30, height: 50 };

    if rect1.width() { // Parentheses indicate method call
        println!("The rectangle has a nonzero width: {}", rect1.width); // No parentheses indicates field access
    }
}
```

## Encapsulation via Getters
Rust does **not** automatically generate getter methods. A common idiomatic pattern is to keep struct fields private while exposing public getter methods:

* Provides **read-only access** to fields.
* Allows internal representation changes without breaking the external public API.

# 4. Automatic Referencing and Dereferencing

In languages like C and C++, separate operators are required based on whether you call a method on an object directly (`.`) or via a pointer (`->`, equivalent to `(*object).method()`).

Rust eliminates the `->` operator through **automatic referencing and dereferencing**:

```rust
// These two calls are functionally identical in Rust:
p1.distance(&p2);
(&p1).distance(&p2);
```

### How It Works
When calling `object.method()`, Rust inspects the method signature and automatically inserts:
* An immutable reference (`&`)
* A mutable reference (`&mut`)
* A dereference (`*`)

Because methods have a clear receiver (`Self`), Rust resolves whether the method needs to borrow (`&self`), mutate (`&mut self`), or consume (`self`) without manual pointer bookkeeping.

# 5. Methods with Multiple Parameters

Methods can accept multiple arguments after the initial `self` parameter:

```rust
impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }

    // Takes an immutable borrow of another Rectangle
    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}

fn main() {
    let rect1 = Rectangle { width: 30, height: 50 };
    let rect2 = Rectangle { width: 10, height: 40 };
    let rect3 = Rectangle { width: 60, height: 45 };

    println!("Can rect1 hold rect2? {}", rect1.can_hold(&rect2)); // true
    println!("Can rect1 hold rect3? {}", rect1.can_hold(&rect3)); // false
}
```

* **Borrowing Parameters**: Passing `&rect2` ensures `can_hold` only reads `rect2`, allowing `main` to retain ownership.

# 6. Associated Functions & Constructors

All functions defined inside an `impl` block are called **associated functions**.

Associated functions that **do not have `self` as their first parameter** are not methods because they operate without an existing instance of the type.

```rust
impl Rectangle {
    // Associated function acting as a constructor
    fn square(size: u32) -> Self {
        Self {
            width: size,
            height: size,
        }
    }
}
```

* **Calling Syntax**: Invoked using the namespace operator `::` on the type name rather than an instance:
  ```rust
  let sq = Rectangle::square(3);
  ```
* **Constructors (`new`)**: Unlike some languages, `new` is not a keyword in Rust. It is simply a community convention for constructor functions (e.g., `String::from` or `Vec::new`).

---

# 7. Multiple `impl` Blocks

A type is allowed to have multiple `impl` blocks across a project:

```rust
impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }
}

impl Rectangle {
    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}
```

* **When to Use**: While not required for simple structs, multiple `impl` blocks become invaluable when organizing large codebases, splitting methods across files, implementing generic types, or conditionally implementing traits based on generic constraints.
