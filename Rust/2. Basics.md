# 1. Conventions & Entry Point

- **File Extension**: Rust source files must use the `.rs` extension.
- **Naming Style**: Multi-word filenames follow `snake_case` (e.g., `hello_world.rs`, not `helloworld.rs`).
- **Main Entry**:
  - `fn main() { ... }` is the entry point for every executable Rust program.
  - The opening brace `{` typically goes on the same line as the function signature, separated by a single space.
  - Rust includes `rustfmt` out-of-the-box for canonical formatting.

---

## 2. Syntax Anatomy

```rust
fn main() {
    println!("Hello, world!");
}
```

### Key Elements:
* **`println!` (Macro, not a function)**:
  * The `!` indicator denotes a **Rust macro** call rather than a regular function.
  * Macros expand code at compile time and follow different syntax/argument rules compared to functions.
* **Semicolon (`;`)**:
  * Ends an expression statement. In Rust (an expression-oriented language), omitting or including a semicolon changes the evaluation behaviour and return value.

# 3. Compilation & Execution Model

Rust is an **Ahead-Of-Time (AOT)** compiled language:
- Code is pre-compiled into a standalone native binary executable.
- The output binary runs on target machines **without needing Rust installed**.

### Manual Compilation via `rustc`
```bash
# 1. Compile source into binary
rustc main.rs

# 2. Run binary
./main       # Linux / macOS / PowerShell
.\main.exe   # Windows CMD
```

> [!note] Output Artifacts
> - **Linux / macOS**: Outputs binary executable named `main`.
> - **Windows**: Outputs `main.exe` and a `main.pdb` debug symbol file.
> - *Note*: Direct `rustc` invocation is only practical for single-file scripts; larger projects use `cargo`.
