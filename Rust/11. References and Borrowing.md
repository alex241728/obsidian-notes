# 1. References & The Borrowing Concept

A **reference** is an address that points to data owned by another variable. In Rust, creating a reference is called **borrowing**.

```rust
fn main() {
    let s1 = String::from("hello");
    let len = calculate_length(&s1); // Passes an immutable reference &s1
    println!("The length of '{s1}' is {len}.");
}

fn calculate_length(s: &String) -> usize { // Borrows s1; does NOT take ownership
    s.len()
} // s leaves scope, but the underlying String is NOT dropped
```

* **No Ownership Transfer**: Because references do not own the underlying data, the referenced value is **not dropped** when the reference leaves scope.
* **Dereferencing Operator (`*`)**: The inverse of borrowing (`&`) is dereferencing via `*` (discussed further with smart pointers).
* **Immutability by Default**: Just like variable bindings, references are immutable by default. Mutating through a standard `&T` triggers compile-time error `E0596`.

# 2. Mutable References (`&mut T`)

To allow a function or scope to modify borrowed data, both the base variable and the reference must be marked mutable:

```rust
fn main() {
    let mut s = String::from("hello");
    change(&mut s);
}

fn change(some_string: &mut String) {
    some_string.push_str(", world");
}
```

## The Core Aliasing / Mutation Invariant
To prevent **data races** at compile time, Rust strictly enforces:
> **You can have either:**
> - **Any number of immutable references (`&T`)**, OR
> - **Exactly one mutable reference (`&mut T`)**,
> **...but never both simultaneously.**

```rust
// ILLEGAL: Multiple mutable references (E0499)
let mut s = String::from("hello");
let r1 = &mut s;
// let r2 = &mut s; // ERROR: cannot borrow `s` as mutable more than once at a time
println!("{r1}");

// ILLEGAL: Mixing immutable and mutable references (E0502)
let mut s = String::from("hello");
let r1 = &s;
let r2 = &s;
// let r3 = &mut s; // ERROR: cannot borrow `s` as mutable because it is also borrowed as immutable
println!("{r1}, {r2}");
```

## What Causes Data Races?
A data race occurs when three conditions align:
1. Two or more pointers access the same memory location simultaneously.
2. At least one pointer performs a write operation.
3. No synchronization mechanism (e.g., mutex) coordinates access.

Rust eliminates data races entirely at compile time via the borrow checker.

# 3. Non-Lexical Lifetimes (NLL)

A reference’s lifetime begins where it is introduced and ends at its **last usage**, not necessarily at the closing curly bracket (`}`):

```rust
let mut s = String::from("hello");

let r1 = &s;
let r2 = &s;
println!("{r1} and {r2}"); // Last usage of immutable references r1 and r2 ends here

let r3 = &mut s; // OK: No active immutable references remain in this scope
println!("{r3}");
```

# 4. Dangling References Prevention

A **dangling pointer** references memory that has been deallocated or reassigned. Rust guarantees at compile time that references will never dangle (`E0106`).

```rust
// ILLEGAL: Returns a reference to stack data that drops at scope exit
fn dangle() -> &String {
    let s = String::from("hello");
    &s // ERROR: s is dropped at the end of dangle(), leaving a dangling pointer!
}

// FIX: Move ownership out directly
fn no_dangle() -> String {
    let s = String::from("hello");
    s // Transfers ownership to the caller
}
```

---

# 5. Summary: The Two Inviolable Rules of References

1. **At any given time, you may have either one mutable reference or any number of immutable references.**
2. **References must always be valid (the compiler prevents dangling references).**
