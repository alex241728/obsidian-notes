**Pattern matching** is one of Rust's most powerful features, allowing developers to compare values against complex structural patterns, bind inner variables, and enforce exhaustive compile-time verification across all possible states.

---

# 1. The `match` Control Flow Construct

The `match` expression evaluates an expression against a sequence of patterns (called **match arms**) and executes the corresponding block for the first matching pattern:

```rust
enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter => 25,
    }
}
```

## Structure of a Match Arm
Each match arm consists of:
* **Pattern**: The shape, literal, or variant to match against.
* **The Fat Arrow Operator (`=>`)**: Separates the pattern from the resultant code.
* **Expression**: The code to execute when the pattern matches.
* **Separators**: Arms are separated by commas. If an arm uses a multi-statement block enclosed in curly braces (`{ ... }`), the trailing comma is optional:

```rust
Coin::Penny => {
    println!("Lucky penny!");
    1 // Implicit return value for this arm
}
```

* **Expression Return**: Like `if`, `match` is an expression; the value of the evaluated arm becomes the value of the entire `match` expression.

# 2. Binding Patterns to Extract Inner Data

Match arms can deconstruct enum variants and **bind variables to the inner data** they contain:

```rust
#[derive(Debug)]
enum UsState {
    Alabama,
    Alaska,
    // --snip--
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter(UsState),
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter(state) => {
            println!("State quarter from {state:?}!");
            25
        }
    }
}
```

* When `Coin::Quarter(UsState::Alaska)` is matched, the variable `state` binds directly to `UsState::Alaska`, making it accessible within that arm's scope.

# 3. Matching with `Option<T>`

`match` is the fundamental mechanism for safely unpacking `Option<T>` into its `Some` and `None` variants:

```rust
fn plus_one(x: Option<i32>) -> Option<i32> {
    match x {
        None => None,
        Some(i) => Some(i + 1), // `i` binds to the inner integer value
    }
}

let five = Some(5);
let six = plus_one(five);   // Some(6)
let none = plus_one(None);  // None
```

# 4. Exhaustive Checking: Preventing Forgotten Cases

In Rust, **matches are strictly exhaustive**. Every possible value in the matched type domain must be accounted for at compile time.

```rust
// ILLEGAL: Fails to handle the None variant
fn plus_one(x: Option<i32>) -> Option<i32> {
    match x {
        Some(i) => Some(i + 1),
    }
}
```

Attempting to compile the above triggers compiler error **`E0004`**:
```text
error[E0004]: non-exhaustive patterns: `None` not covered
 --> src/main.rs:3:15
  |
3 |         match x {
  |               ^ pattern `None` not covered
```

> [!important] Compile-Time Null Safety
> By enforcing exhaustive pattern matching on `Option<T>`, the compiler makes it impossible to forget checking for absent values (`None`), preventing null-pointer bugs at compile time.

# 5. Catch-All Patterns & The Wildcard (`_`)

When you only care about specific cases and want a default action for everything else, Rust provides catch-all patterns.

## Catch-All with Value Binding
Use a variable name as the final arm pattern to capture and use any unmatched value:

```rust
let dice_roll = 9;

match dice_roll {
    3 => add_fancy_hat(),
    7 => remove_fancy_hat(),
    other => move_player(other), // Binds any other u8 value to `other`
}

fn add_fancy_hat() {}
fn remove_fancy_hat() {}
fn move_player(num_spaces: u8) {}
```

> [!note] Evaluation Order
> Match arms are evaluated sequentially. A catch-all pattern **must come last**; placing it before specific patterns causes subsequent arms to be unreachable.

## The Wildcard (`_`) Placeholder
When you do not need to use the unmatched value, use the underscore (`_`) wildcard to discard it without triggering unused variable warnings:

```rust
match dice_roll {
    3 => add_fancy_hat(),
    7 => remove_fancy_hat(),
    _ => reroll(), // Matches any other value, discarding it
}

fn reroll() {}
```

## No-Op Matching with the Unit Tuple `()`
To take **no action** on unmatched variants, return the unit type `()`:

```rust
match dice_roll {
    3 => add_fancy_hat(),
    7 => remove_fancy_hat(),
    _ => (), // Explicitly do nothing for any other roll
}
```

# 6. Concise Control Flow: `if let`

When you only need to match **one specific pattern** and ignore all others, `match` with `_ => ()` introduces unnecessary boilerplate:

```rust
// Verbose match:
let config_max = Some(3u8);
match config_max {
    Some(max) => println!("The maximum is configured to be {max}"),
    _ => (),
}
```

## The `if let` Shorthand
`if let` provides clean syntax sugar for a single-arm match:

```rust
let config_max = Some(3u8);

if let Some(max) = config_max {
    println!("The maximum is configured to be {max}");
}
```

* **Trade-off**: `if let` saves typing and indentation, but forfeits the exhaustive checking that `match` strictly enforces.

## Adding an `else` Block
`if let` can be combined with `else` (equivalent to the `_` fallback arm):

```rust
let mut count = 0;

if let Coin::Quarter(state) = coin {
    println!("State quarter from {state:?}!");
} else {
    count += 1;
}
```

---

# 7. Staying on the "Happy Path": `let...else`

When a function needs to extract inner data or return early on mismatch, nested `if let` statements can push core logic deep into indented blocks. 

The `let...else` statement allows bindings to escape to the **outer scope** while requiring diverging control flow in the `else` block:

```rust
fn describe_state_quarter(coin: Coin) -> Option<String> {
    // Guards and binds `state` to the outer function scope:
    let Coin::Quarter(state) = coin else {
        return None; // The `else` block MUST diverge (return, break, continue, panic)
    };

    // Stays on the flat "happy path" without indentation:
    if state.existed_in(1900) {
        Some(format!("{state:?} is pretty old, for America!"))
    } else {
        Some(format!("{state:?} is relatively new."))
    }
}
```

# 8. Pattern Matching Construct Comparison

| Construct | Exhaustiveness | Scope of Bindings | Primary Use Case |
| :--- | :--- | :--- | :--- |
| **`match`** | **Strictly required** (enforced by compiler) | Local to matching arm | Handling multiple variants / discrete states. |
| **`if let`** | None (silently ignores non-matching) | Scoped inside `if` block | Executing side effects for a single variant. |
| **`let...else`** | None (explicit divergence required) | **Available in outer scope** | Guard clauses / early returns that unwrap data. |
