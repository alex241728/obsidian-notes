Ownership is Rust's central feature for managing heap memory without an automatic garbage collector (GC) or explicit manual deallocation (`free`/`malloc`). All ownership checks occur at compile time with zero runtime performance cost.

---

# 1. The Stack vs. The Heap

| Characteristic | The Stack | The Heap |
| :--- | :--- | :--- |
| **Data Sizing** | Fixed, known size at compile time | Dynamic or unknown size at compile time |
| **Structure** | LIFO (Last In, First Out) | Unorganized pool; allocator searches for a free block |
| **Speed** | Extremely fast (push/pop at top of stack) | Slower (allocator bookkeeping + pointer traversal) |
| **Locality** | High CPU cache locality | Lower cache locality (pointer chasing across memory) |
| **Contents** | Primitive types, pointers, local function frames | Dynamically sized contents (e.g., `String` data payload) |

---

# 2. The Three Ownership Rules

1. **Each value in Rust has an owner.**
2. **There can only be one owner at a time.**
3. **When the owner goes out of scope, the value is dropped.**

---

# 3. Memory Deallocation & RAII

Rust frees heap resources automatically once the variable owning the resource leaves scope using the **`drop`** function (equivalent to C++'s RAII: Resource Acquisition Is Initialization):

```rust
{
    let s = String::from("hello"); // s allocates on the heap
    // do work with s
} // Scope closes -> Rust calls `drop` automatically -> memory returned
```

---

# 4. Move Semantics vs. Clone

A `String` on the stack consists of three fields: **pointer** to heap memory, **length**, and **capacity**.

## Move (Default for Non-Copy Types)
Assigning one heap-backed variable to another copies the stack metadata (pointer, length, capacity) and **invalidates** the original binding:

```rust
let s1 = String::from("hello");
let s2 = s1; // Shallow copy of stack metadata + s1 is invalidated (MOVED)

// println!("{s1}"); // ERROR: E0382 (borrow of moved value)
```

* **Prevents Double Free**: Since `s1` is invalidated, only `s2` frees the heap allocation upon going out of scope.
* **Zero Hidden Deep Copies**: Rust never implicitly duplicates large heap structures.

## Clone (Explicit Deep Copy)
To duplicate heap contents alongside stack metadata, call `.clone()`:

```rust
let s1 = String::from("hello");
let s2 = s1.clone(); // Fully duplicates heap buffer; s1 remains valid
```

---

# 5. The `Copy` Trait (Stack-Only Types)

Types stored entirely on the stack do not own heap resources. Assigning them duplicates the bits without invalidating the source:

```rust
let x = 5;
let y = x; // Copied trivially
println!("x = {x}, y = {y}"); // Valid: i32 implements Copy
```

* **Rules for `Copy`**:
  * Any simple scalar type: all integers (`i32`, `u64`), floats (`f64`), booleans (`bool`), characters (`char`).
  * Tuples containing **only** types that implement `Copy` (e.g., `(i32, i32)` is `Copy`; `(i32, String)` is **not**).
  * Any type implementing `Drop` **cannot** implement `Copy`.

---

# 6. Ownership in Functions

Passing arguments and returning values follows the exact same move/copy semantics as variable assignment:

```rust
fn main() {
    let s = String::from("hello");
    takes_ownership(s); // Heap pointer moved into function; s is now invalid!

    let x = 5;
    makes_copy(x);      // i32 copied; x remains valid!

    let s1 = gives_ownership();         // Moves return value into s1
    let s2 = takes_and_gives_back(s1);  // s1 moved into fn, returned into s2
}

fn takes_ownership(some_string: String) {
    println!("{some_string}");
} // some_string dropped here

fn makes_copy(some_integer: i32) {
    println!("{some_integer}");
}

fn gives_ownership() -> String {
    String::from("yours") // Ownership moved to caller
}

fn takes_and_gives_back(a_string: String) -> String {
    a_string // Ownership moved to caller
}
```

> [!tip] Transition to References
> Transferring ownership back and forth via return tuples (`(String, usize)`) introduces unnecessary boilerplate. Rust resolves this cleanly through **references and borrowing** (`&T` and `&mut T`), allowing data access without transferring ownership.
