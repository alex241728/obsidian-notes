Rust is a **statically typed** language. The compiler must know the types of all variables at compile time through inference or explicit type annotations (e.g., `let x: u32 = ...`).

---

# 1. Scalar Types

Scalar types represent a single value. Rust features four primary scalar types:

## Integers
Numbers without a fractional component.

| Length             | Signed (`i`)      | Unsigned (`u`) | Range Formula                                                   |
| :----------------- | :---------------- | :------------- | :-------------------------------------------------------------- |
| **8-bit**          | `i8`              | `u8`           | Signed: $-(2^{n-1})$ to $2^{n-1}-1$<br>Unsigned: $0$ to $2^n-1$ |
| **16-bit**         | `i16`             | `u16`          |                                                                 |
| **32-bit**         | `i32` *(default)* | `u32`          |                                                                 |
| **64-bit**         | `i64`             | `u64`          |                                                                 |
| **128-bit**        | `i128`            | `u128`         |                                                                 |
| **Arch-dependent** | `isize`           | `usize`        | 64-bit on x86_64; used primarily for collection indexing        |

* **Literals**: Decimal (`98_222`), Hex (`0xff`), Octal (`0o77`), Binary (`0b1111_0000`), Byte (`b'A'`).
* **Visual Separator**: `_` improves readability (e.g., `1_000` is identical to `1000`).
* **Integer Overflow**:
  * **Debug Mode**: Rust includes runtime overflow checks that trigger a **panic**.
  * **Release Mode (`--release`)**: Overflow checks are stripped. Rust performs **two's complement wrapping** (e.g., in `u8`, 256 wraps to 0). Relying on this is considered a bug.
  * **Explicit Standard Library Handlers**: `wrapping_*`, `checked_*`, `overflowing_*`, and `saturating_*`.

## Floating-Point Numbers
* **Types**: `f32` (single-precision) and `f64` (double-precision, default).
* All floating-point types are signed and adhere to the **IEEE-754** standard.
* Integer division (`/`) truncates toward zero (e.g., `-5 / 3` evaluates to `-1`).

## Booleans
* Type: `bool`.
* Values: `true` and `false`.
* Memory footprint: **1 byte**.

## Characters (`char`)
* **Size**: **4 bytes** (32 bits).
* Encodes a **Unicode Scalar Value** (ranges: `U+0000..=U+D7FF` and `U+E000..=U+10FFFF`).
* Literals use **single quotes** (`'z'`, `'ℤ'`, `'😻'`), whereas string literals use double quotes (`"..."`).

# 2. Compound Types

Compound types group multiple values into a single type.

## Tuples
Group multiple values of **differing types** into a **fixed-length** collection.

```rust
let tup: (i32, f64, u8) = (500, 6.4, 1);

// Destructuring via pattern matching
let (x, y, z) = tup;

// Direct element access via dot notation
let five_hundred = tup.0;
let six_point_four = tup.1;
```

* **Unit Type `()`**: A tuple with zero elements. Represents an empty value or an implicit return type for expressions/functions that do not explicitly return a value.

## Arrays
Group multiple values of the **same type** into a **fixed-length** collection allocated contiguously on the **stack**.

```rust
// Explicit type annotation: [Type; Length]
let a: [i32; 5] = [1, 2, 3, 4, 5];

// Repeat expression: [Value; Length] -> [3, 3, 3, 3, 3]
let repeated = [3; 5];

// Indexing access
let first = a[0];
```

| Type | Size Flexibility | Memory Location | Best Used When |
| :--- | :--- | :--- | :--- |
| **Array (`[T; N]`)** | Fixed length | Stack | Number of elements is strictly constant (e.g., months of the year). |
| **Vector (`Vec<T>`)** | Dynamically growable | Heap | Element count can expand or shrink at runtime. |

# 3. Memory Safety: Bounds Checking

Rust enforces runtime bounds checking when indexing arrays (`a[index]`):

```rust
let a = [1, 2, 3, 4, 5];
let element = a[10]; // PANIC at runtime
```

* If `index >= length`, Rust terminates execution with a **runtime panic** (`index out of bounds`).
* Prevents accessing unallocated or unauthorized memory locations (a common source of buffer overflow vulnerabilities in C/C++).
