# Capacities

- **On-Demand Provisioning**: Create or delete virtual machines in minutes. 
- **Flexible Scaling**: Resize instances or add resources as workloads change. 
- **Full OS & Software Control**: Install and configure your own software.
- **Usage-Based Cost**: Pay for provisioned resources based on usage.

---

# Common Use Cases 

- Web hosting (e.g., Nginx) 
- Self-managed databases (e.g., PostgreSQL) 
- Development and testing environments 
- Compute-intensive workloads (analytics, batch jobs) 
- Backup and disaster recovery

# Resources

## Compute

 Provide processing power for running applications 
 
 - **Virtual machines** (e.g., AWS EC2, DigitalOcean Droplets)
 - Configurable CPU, memory, OS (e.g., Ubuntu, CentOS) 
 - Behave much like physical servers, but are: 
	 - **Virtual**: Run on virtualized hardware 
	 - **Easy to provision**: Can be created and deleted quickly 
	 - **Resizable**: CPU and memory can often be changed; storage can usually be expanded

---

## Storage

### Block Storage

Provides raw storage volumes, like a virtual hard drive

- Attached to a VM
	- Requires formatting (create a file system) and mounting (OS treats this storage as a local folder)
- Designed for low-latency reads and writes
- Used for: Databases, OS disks, applications requiring frequent reads/writes

**Examples**: AWS EBS, DigitalOcean Volumes

Think of it as plugging an external SSD into your VM

---

### Object Storage

Stores unstructured data as objects (data + metadata)

- Not mounted like a disk
- Accessed over the network through HTTP-based APIs
- Highly scalable: No need to provision or resize disks
- Durable: Objects are stored redundantly
- Used for: Images, videos, backups, static website assets

**Examples**: Amazon S3, DigitalOcean Spaces

Think of it as a web-accessible bucket of files

---

### File Storage

Provides a shared file system over a network

- Provider-managed shared file system
- Multiple VMs can access the same files
- Each VM mounts the file system as a directory (e.g., /mnt/shared)
- Uses for: Shared application data, workloads requiring a common file system

Examples: Amazon EFS, DigitalOcean NFS

Think of it as a networked shared folder

---

## Networking

Control how cloud resources communicate internally and with the Internet

- VPC: Isolated virtual network
- Load Balancer: Distribute traffic across VMs
- Firewall/Security Group: Control allowed network traffic
- Public & Private IP Addresses, DNS, …

Example: Amazon VPC, DigitalOcean Cloud Firewalls

> [!info] VPC vs. VPN & How They Work Together
> - **VPC (Virtual Private Cloud)**: A virtual private network inside the cloud. Provides isolated internal networking for cloud resources.
> - **VPN (Virtual Private Network)**: A secure, encrypted connection used to reach a private network over the Internet. Provides secure remote access to a private network (remote-access VPN or site-to-site VPN).
> - **Key Relationship**:
>   - A VPN can connect users or networks to a VPC, but a VPC can exist and operate without a VPN.
> - **A Common Cloud Setup (VPC & VPN used together)**:
>   - A VPC hosting cloud infrastructure.
>   - A VPN providing secure access for Developers $\rightarrow$ VPC or On-Prem Data Center $\rightarrow$ VPC.
>   - *Example*: A company deploys internal dashboards on VM instances inside a VPC; engineers connect through company VPN to securely reach those dashboards.

# Management Interfaces

- **Web Dashboard**: Point-and-click interface in a browser
- **CLI (Command-Line Interface)**: Text-based tool for managing resources with commands
	- Useful for fast, repeatable actions (e.g., `doctl compute droplet create <droplet-name>`)
- **API (Application Programming Interface)**: Lets software interact with the cloud directly
	- Used for automation and integration
