**Make everything streaming? No!**
- Serial algorithms/decisions $\to$ No speed up vs. microprocessor
- Low performance requirements $\to$ No need for speed up
- Processor is very area-efficient at re-using hardware compute units

**Make a mixed device?**
- High throughput computation: Streaming
- Control/Serial/Low Performance: Microprocessor
- ![[mixed_device.png]]
- This is the most modern ASICs (custom chips) & FPGA systems (More flexible than all streaming hardware)

# Singe-Rate Synchronous Dataflow

- Static operators
- Data flows through all operators at same rate
- Efficient in FPGAs
- Can pipeline to increase parallelism
- Want cuts:
	- With equal logic on both sides
	- With few edges (registers)
- Can't pipeline a loop

![[single-rate_synchronous_dataflow.png]]

# Synchronous Dataflow

- What if some operators produce more outputs than input?
	- E.g. Interpolation filter
- Or vice versa?
	- E.g. Decimation filter

- Can't run everything at same rate
- Use **data valid** tag/synchronize data.

![[synchronous_dataflow.png]]
- Feed forward control: G executes when both inputs valid.
- Choose speeds/copies of $F_{1}$, $F_{2}$, $G$ such that no valid data dropped.

# Dynamic Streaming Dataflow
- What if time to produce data varies?
	- E.g. Newton-Raphson iteration
- What if amount of data varies?
	- E.g. Huffman encoding
- Don't want to (or can't) worst case time/data size

- Convert some pipeline registers to FIFOs.
	- Decouple operators
- Can't bound computation imbalance?
	- Add back-pressure signals
	- Assert in time to avoid b

# Streaming Dataflow with Allocation

- Can change operators or connections over time
## Method 1

- Build extra flexibility in operators
- Building maxing into interconnect
- Expensive in FPGAs

![[streaming_dataflow_with_allocation_method_1.png]]

## Method 2
- Reconfigure part of FPGA

![[streaming_dataflow_with_allocation_method_2.png]]
- Difficult design flow
- Why? (Processors do all the time with virtual memory)
	- $F_{1}'$ must fit in physical space of $F_{1}$ (same logic, RAM, DSP)
	- Interface & signals and physical wires at edge of $F_{1}'$ and $F_{1}$ must match.
	- $F_{1}'$ outputs (inputs to G) must go to reasonable state (e.g. valid = 0) during reconfig.
	- Reconfig fairly slow (~ 100 ms * % of chip).
